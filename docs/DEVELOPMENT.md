# 拾事开发规范

所有参与开发的人和 AI 都必须遵守本规范。与 `AGENTS.md` 的具体约定冲突时以 `AGENTS.md` 为准；本规范没写到的，按“更少的代码、更少的资源、更少的打扰”取舍。

## 1. 代码

- 每一行都要能回答“删掉它会坏什么”。答不上来就不写：不写用不到的参数、字段、配置项、分支、日志和注释。
- 适度封装：一段逻辑在两处以上真正复用、或单独命名后明显更好读，才抽函数或类型。只有一个实现的 trait、只转发一层的包装、为“以后可能扩展”预留的接口一律不加（测试替身确有需要的除外）。
- 不重复：同一规则只在一处实现；能用 SQL 一次表达的不在 Rust 里再过滤一遍，反之简单逻辑也不硬塞进复杂 SQL。
- 删除优先于新增。改需求时连带删掉被替代的代码、字段、样式、提示词和文档，不留兼容层和“暂时保留”。
- 注释只写代码表达不了的“为什么”：约束、取舍、外部系统的行为。不写复述代码的注释和变更历史。
- 不引入新依赖、框架或组件库，除非现有依赖确实做不到且收益明确；引入时固定版本并更新 `THIRD_PARTY_NOTICES.md`。
- 前端沿用现有原生 JS 与 CSS：字号、颜色、间距、圆角只用 `tokens.css` 中的语义变量，不写死数值。

## 2. 错误处理

- 以任务为边界统一处理。内部调用出错直接用 `?` 上抛，不在中间层捕获、改写、吞掉或补默认值。
- 任务边界（AI 分析、归档、扫描、处置、更新等一次执行）负责三件事：记录一条日志、完成必要清理（释放执行位置、关闭进程或会话、恢复运行状态）、结束本次执行。影响限制在当前任务，主流程和其他任务照常运行。
- 除非需求明确要求，不重试、不兜底、不降级，也不为某种异常单独写分支。下一次正常触发就是重试。
- 只校验外部输入（用户输入、聊天数据、插件和模型的输出、文件内容），校验一次，在入口处。内部之间传递的数据不重复校验，不检查不可能出现的状态。
- 错误信息写给用户看：说清楚哪一步失败、用户能做什么，不暴露密钥和本机路径。

## 3. 开关与设置

- 只为用户需要选择的行为加开关；能定一个合理默认值的就不做成设置。
- 开关关闭等于功能不存在：不启动线程或进程、不轮询、不建窗口、不占内存和磁盘，也不产生日志和提醒。重新打开立即生效，不需要重启。
- 依赖关系写在一处并在界面说明，例如关闭增量扫描后自动分析和提前触发随之暂停；不另设一组互相牵制的开关。
- 一个开关只管一件事，名称直接写它启用了什么。不加隐藏开关、调试开关和“高级”兼容开关。
- 显式手动操作不受工作时间、节假日和自动开关限制，但仍遵守额度、权限、取消和校验。

## 4. 资源

- 一切由事件驱动：按真实截止时间休眠，不写固定间隔的轮询和 sleep 循环。
- 按需创建：窗口、WebView、子进程、连接在第一次需要时创建；不用时隐藏或释放，并降低 WebView 内存级别。
- 按需读取：数据库按页面和范围查询，有大小上限；不做全量加载，不在内存里长期缓存可以重新读取的数据。
- 磁盘只写有用的东西：诊断日志遵守保留设置，临时文件用完即删，不写重复的快照和备份。
- 安装包和二进制尽量小；新增功能要说明对体积、内存和 CPU 的影响，未实测不声称达标。

## 5. 不打扰用户

- 平时安静运行，只在需要用户决定或用户关心的结果出现时提醒，每件事提醒一次。
- 提醒不抢焦点、不弹模态框、不强制前置窗口；能用托盘、底栏或事项状态表达的就不弹窗。
- 后台任务不打开或切换用户正在使用的客户端窗口；需要交接时由用户点击触发。
- 不在用户没有操作时修改其提示词、标签、规则或个人配置；建议一律等用户采用。没改过的内置提示词随版本更新，不算修改。
- 失败只在用户能做点什么时才提示，其余写日志。

## 6. 交付

- 改完先跑相关测试，提交前跑 `python3 scripts/test.py`。新功能和修复要有离线测试，使用合成数据，不调用真实模型。
- 只能在 Windows 上验证的行为，列出验收步骤交给用户实测，不声称已验证。
- 提交说明一句中文描述，不附正文和署名行。
