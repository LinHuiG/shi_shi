# AI 处置与紧凑上下文

## 接入与工作状态

分析、处置、归档和消息过滤只有在工作或加班状态才能发起 AI 请求；消息扫描始终继续。下班到点仍有一个持久化下班 claim 且对应归档 attempt 为 queued/running 时，归档是唯一的例外。业务日和加班按上海最近一次 `work_start` 计算，跨零点时同一班次使用开始日的日历和业务日。

处置可选择 Codex CLI 或新版 DeepSeek Harness。两者都通过统一的会话 DTO 暴露项目、轮次、审批、取消、历史和用量；Harness 不支持的重命名或运行中插话会明确报错。官方 OpenAI Chat Completions 兼容 API 只用于结构化分析，不提供处置会话。

## 项目选择与执行

消息分类和手动事项整理会附带当前可用的 Codex 项目清单（最多 60 个）。AI 返回项目编号及理由；证据不足、无合适项目或候选有歧义时应留空。程序丢弃不在提供清单中的项目编号。打开一键处置时再次核对项目是否有效，只预选，不自动启动，用户确认后开始执行。已有事项没有推荐值时仍可手动选择；用户明确配置的项目匹配规则也可用于预选。

每个处置记录使用独立 app-server 进程。原始连接通过 JSON-RPC 通知推送可见进展、工具状态、待审批请求和用量；后台合并约 150 毫秒内的事件后刷新，不为每个文本片段查询完整历史。每 30 秒查询历史用于补全漏失事件、最终记录和断线状态。查询不触发模型调用。

## 审批范围

- 仅允许本次：批准当前命令或文件变更；权限工具的对应选项为“允许本轮权限”。
- 本会话允许：采用 Codex 的会话授权决定，不会关闭所有审批。权限工具仅保留当前请求中列出的权限。
- 允许类似命令：只在 Codex 提供可用参数前缀规则时出现；显示完整规则。规则可能在后续会话生效，不能当作仅批准当前命令。
- 全部批准：先展示当前完整请求的清单，只批准该快照中的请求。之后新增的请求、信息不完整的请求、补充问题及外部服务授权不包括在内。批量操作不能保证原子性；中途失败时提示同步并核对剩余请求。

服务端声明 `availableDecisions` 时，界面及 Rust 处理逻辑都遵守该清单。文件审批从相同 thread/turn/item 的执行记录补全文件列表，缺少详情不直接允许。原始 JSON 保留在折叠的技术详情内。

## 交接到 Codex

点击“交接到 Codex”后明确确认停止当前轮。程序调用中断并查询轮次，确认已停止后才关闭该事项专用的后台进程，释放会话，然后打开同一会话的 Codex 链接。请在 Codex 中手动恢复，待处理审批可能需要重新发起。

交接不会停止其他事项的独立后台。交接标记与执行状态分别持久保存；之后拾事拒绝对此会话追问、审批、中断或恢复连接，仅只读同步。打开桌面失败可以重试而不再次中断。创建后即可单独打开客户端查看，打开本身不交接控制权。

Codex 首次创建处置会话时，通过配置 RPC 合并登记固定的 `mcp_servers.shishi_context` 接入，保留其他 MCP 配置。固定服务由 Codex 独立启动，使用 `--context-mcp-root` 和每次工具调用必需的 `context_token`；不能指定文件路径、列出凭证或推断当前事项。交接前校验接口可用性，把事项凭证说明持久写入原会话，不发起模型轮次，然后释放原后台。原有已交接会话可以从“上下文续接说明”取得固定接入和凭证，手动粘贴到原会话；客户端尚未加载新配置时需刷新 MCP 或重启。授权过期可在拾事点击同步状态续期，服务端始终检查事项范围、撤回和分页限制。

已交接会话优先只读观察 Codex 返回的该会话记录路径，核对会话元数据后有界读取追加的公开开始/完成事件；不恢复或接管桌面会话。运行或等待同步时每5秒补查历史，空闲时30秒校准。未知记录格式、未返回路径或无法确定当前状态时显示“已交接到 Codex · 等待同步”；旧的停止记录不冒充桌面当前状态。记录观察属于兼容回退路径，不能将它当成所有 Codex 版本都具备的跨进程订阅接口。

测试使用模拟协议进程，不会停止真实会话或调用模型；实际桌面接管依赖所安装 Codex 版本与 URL 协议注册，仍需安装后的真实使用验证。

## 过程、时间与 Markdown

过程记录展示 Codex 返回的公开进展、命令及输出、文件差异、工具与上下文查询；不记录内部推理正文。每轮最多保留 200 项可见过程，每项最多 6000 字符，完整记录仍以 Codex 为准。上下文审计保存查询条件和原始证据编号，不复制全量消息库。

本轮时长优先使用 Codex 的 `durationMs`，否则使用明确的开始/完成时间差；运行中使用已知开始时间展示已耗时。它包含工具执行与等待审批，并非纯模型推理时间。缺失时间显示未知。“从开始至今”单独展示事项处置的墙钟时间。

Markdown 支持标题、段落、列表、引用、强调、行内代码、代码块、简单表格和 HTTP(S) 链接。不执行原始 HTML，不加载 Markdown 图片，不接受脚本或 data URL。命令和文件差异按文本转义。

## 可逆压缩

`wire_context.rs` 位于模型边界，原始存储不改格式：

1. 本次分析的消息和事项编号映射为短编号，映射仅保留在程序内及本地上下文授权文件，不发给模型。模型结果先回映，再进行证据检查、标签收集和事项写入；未知短编号拒绝应用。
2. 消息用固定列数组，`message_cols` 定义每列；聊天元数据只在 `rooms` 中出现一次。缺失单元格用 null 占位。
3. 删除空值、检索排名及模型不使用的检索统计；分类字段与标签完全相同时只留分类字段。保留不同的自定义标签。
4. 不合并不同消息、不改写原文；保留时间、回复编号、否定词、账号等正文事实、截断标记及证据边界。已有的检索和分页上限继续生效，长资料按需读取。
5. 延续增量输入和字段差异输出，不重复发送全部历史。处置首条输入只给标题和调查要求，详细事项及相关证据通过限范围上下文接口读取，避免重复。
6. 处置上下文短编号在同一 run 内稳定；授权续期保留已有映射，审计仍保存真实编号。源记录撤回或不在范围内时不能因存在旧映射而读取。

压缩说明本身也有开销：分析输入只有在压缩后的公开载荷字符数更小时才启用，否则保留原表示。日志 `wire_chars.before/after` 记录字符量，不含映射和私有上下文全文；这不是 tokenizer 的精确 token 数，不保证固定比例的费用下降。未采用 gzip、Base64 或额外模型摘要来压缩消息。
