## 修复与行为

- 手动刷新分析、手动归档、新建整理、处置、报表及其他手动 AI 用途不受上下班、假期、日历未知或是否加班限制。自动请求仍受原工作状态门禁约束；配额、工具权限、取消、输入及结果校验继续执行。手动归档的新尝试编号只关联本次操作，不复用已结束的自动归档。
- Codex 返回线程编号时，其 rollout 可能尚未持久化。前台元数据更新与打开操作移至独立线程，在确认本次线程可读后执行；只对明确的 rollout 尚未出现做有界等待，未知内部错误不重试，不重复调用模型。
- `exec --json` 条目快照不能保证逐字返回。除实际 JSONL 文本与工具/生命周期阶段外，在 CLI 提供本次新线程的磁盘路径时，补充读取该线程公开的摘要和响应事件；支持分块 UTF-8、有界记录与队列，忽略原始 reasoning、加密项和其他会话。前台打开失败不阻止已可读取的公开进度；没有公开内容时如实显示阶段。
- 归档默认提示词、固定权限协议、输入与动态 schema 统一要求：归档记忆只能引用本批事项归档备注。请求提供明确的 `archive_note_sources`，schema 限定其编号；没有备注时记忆变更必须为空。不覆盖已有用户提示词，不放宽来源校验，不静默删除错误变更、不自动重试。
- 旧“归档完成”实际只表示模型响应返回，之后可能因来源校验或保存失败而未提交业务效果。日志现在明确区分“归档响应已返回”“归档已提交”“归档提交失败”，最终提交/失败均可在 AI 记录、归档用途及异常筛选中查看。失败保留材料、事项与游标，继续原子提交。
- 底部保持原有单行，待分析管理入口放在最右，中间随收到的公开内容显示最新消息行，移除模型名、来源与接收时间等冗长信息；长内容及窄窗口截断。取消、展开预览、安全转义、滚动位置与请求隔离继续有效。阶段更新不冒充供应商已返回文本。
