# 工具调用

事项分析、生成、一句话修改和归档都可以使用用户注册的 CMD 工具。首次请求直接声明实际可用工具，模型选择调用后由拾事（SS）执行，按调用编号回传结果，在同一业务请求中继续，最终返回原用途的结果格式。调用始终沿用当前用途的接入与模型，不存在单独的工具模型配置。

## 配置与使用

在“系统提示词 → 工具调用 → 工具列表”管理工具；这个提示词类型是共用能力说明。新工具默认关闭，填写工具名、使用说明和 CMD 命令即可；工具名可由明确的脚本或程序名建议，仍可修改。命令里的 `{{参数名}}` 自动补出参数行，只需补充参数说明，已有人工填写不会被覆盖。所有参数均为字符串，业务类型、默认值、校验和解析由脚本处理。

启用开关位于编辑器右上角；未完成配置可以关闭保存。所有事项及消息批次、生成、一句话修改和归档统一使用全局已启用且兼容的工具，不需要事项级开关；旧事项名单仅保留历史数据，不再限制调用。消息文字不能修改工具注册和全局开关。没有可用工具或无需调用时，正常返回当前业务结果。

工具列表每行只保留开关、编辑和删除入口，顶部“调用记录”查看全局历史。进入编辑后展开“测试运行”，每个参数有一个文本样例输入。预览命令、测试、取消和结果查看都在本地完成，无需模型；测试执行当前草稿，留下调用记录，不自动保存或开启工具。“复制工具制作提示词”使用当前草稿在本地生成文本，不启动模型或其他 agent。自动复制不可用时提供已选中的完整文本，关闭后恢复编辑草稿。提示词页保留编辑和工具列表，不再显示单独的最终提示词预览按钮。

## 参数与输出

每个 `{{参数名}}` 独占一个参数，外面不加引号。例如 `record-tool.exe --id {{record_id}}`，`DEMO 001` 作为一个完整参数传入。省略参数替换为空字符串；显式数字、布尔值、对象、数组、未知参数和未定义占位符在执行前拒绝。

SS 使用 `cmd.exe /d /v:off /s /c`，关闭 AutoRun 和延迟变量展开。客户命令继承进程环境；需要特定目录时在包装脚本中处理。参数包含空格、中文及 `& | < > ^ ! ( )` 时使用完整引用。为避免 CMD 和 BAT 二次解析改变数据，值中的双引号、百分号、控制字符或末尾反斜杠明确拒绝；复杂输入可使用客户工具约定的编码字符串。模板不支持在已有引号内或单个选项中嵌入占位符。

stdout 和 stderr 严格按 UTF-8 解码；不猜测或配置其他编码。无效字节保留退出状态并显示输出错误。每条命令固定最多 60 秒，每工具每分钟 60 次，测试共享稳定工具 ID 的计数。全部续轮受当前 AI 总期限、取消和输入预算约束，命令上限不会延长总期限。

## 执行与记录

- 非一键处置用途统一由 SS 调度。API 使用原生结构化工具请求；Codex / DSH 作为普通模型后端返回结构化文本，由适配层转换到同一个 API 工具循环。SS 解析和校验参数，执行 read_context、read_image 或注册业务工具，再把真实结果回传模型，直到取得最终业务结果。非处置链路不注册业务工具 MCP 函数。
- Codex / DSH 的文本响应固定为 `{tool_call, result}`，一次工具请求与最终业务结果互斥。工具请求的 `name` 来自本次冻结目录，`arguments` 是参数对象编码成的 JSON 字符串，沿用 API 的解析器；注册业务参数只接受字符串，补查按自己的 schema。图片作为原生图片内容回传，base64 不放进普通提示词正文。各续轮共用总期限、取消和预算，已报告用量跨轮累加，失败保留已知部分。
- AI 一键处置沿用 MCP 服务，只增加通用 `ss_tool(context_token, tool_name, arguments)`，业务工具不逐个注册为 MCP 函数。`context_token` 沿用现有事项凭证，两个业务参数分别为工具名和字符串参数对象；可用目录从 `get_task_context.available_tools` 取得。MCP 子进程向运行中的 SS 转交请求，由同一个执行器执行、持久记录并关联对应事项。没有新增区分其他聊天或用途的禁止调用规则。
- 声明与文字目录来自同一冻结集合；配置编辑用于下一次请求。每次启动前再次检查实时开关，关闭后阻止后续命令。取消或超时回收本次拥有的 Windows Job 子进程树。
- 先持久保存调用意图，再执行并保存结果；保存意图失败不执行。相同调用 ID 不重放，网络失败或结果未知也不自动重试。调用记录保存工具稳定 ID、用途、请求和调用编号、可选事项关联、时间、参数、状态、退出码和有界输出。
- stdout 和 stderr 并行排空，各保留最多 32 KiB，超限标记截断；回传模型的副本还受续轮预算约束，不重复执行以索取完整输出。
- 工具列表和有实际关联调用的事项均可查询记录；事项入口位于外侧操作区的“合并”后，无记录时不显示；“无需处理”等状态选项收在完成按钮的悬停菜单中。记录按单次调用列出工具 name、时间、调用方式、执行结果和参数，支持紧凑筛选及多关键词模糊搜索，过滤后分页，每页最多 20 条。点击整行查看分区详情，参数与标准／错误输出独立展示，编号默认折叠；关闭逐层返回并保留筛选。事项入口固定当前事项范围，不显示额外事项筛选框；批量分析与生成通过各项结果的 `tool_call_ids` 关联实际调用编号，不把整批调用挂给所有事项。仅接纳当前请求中存在的调用编号和已通过版本／证据校验的事项；上下文中出现的其他事项不自动关联。旧记录若只有唯一事项可沿用，旧多事项批次没有明确逐条归属时保留在全局记录，不按文字推测。系统日志的“工具调用”合并检索测试和业务调用，原用途事实保留；大段输出保存在既有 SQLite 明细，不重复写入 JSONL。
- 工具列表可以点击软件内其他区域关闭；编辑器、记录列表和详情不会随外点或操作系统失焦关闭。关闭详情返回记录列表，关闭记录列表返回原入口；列表搜索和编辑草稿保留。
- 旧工具中非字符串类型、默认值、约束、非 UTF-8 或非默认执行设置不静默转换或执行。编辑器说明兼容问题，用户检查包装命令后明确重新保存为简化定义；原历史与绑定保留。旧独立模型配置只保留兼容读取，没有执行入口；旧记录缺失用途或来源时不推测补全。

命令结果不直接改变事项状态、提示词、标签或记忆；最终写入仍遵循当前用途的校验和事务边界。原始响应诊断沿用完整跟踪设置和本地清理。离线回归见 [开发说明](DEVELOPMENT.md)，默认不使用真实模型或真实业务命令。
