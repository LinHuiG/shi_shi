# ShiShi 1.1.5

本版处理 SS-104—SS-111：统一消息依据、收紧日志和设置界面，并修复消息重复入队与过滤反复触发。

- 三类依据在前端合并去重，保留后台角色与完成校验；默认时间正序，可切换倒序；按正文、发送人、会话和来源进行不区分大小写的部分关键词搜索，多个空格分隔关键词共同匹配。总数按实际可展示的去重消息统计，搜索显示匹配数和总数。
- 收件箱选择与删除操作进入首行，时间控件和行间距紧凑化；新增针对整个查询的时间正序/倒序，默认倒序，排序切换回到首页并清空选择。
- 删除日志页整行 token 说明，保留统计；收紧日期、数字、时间、用途和模型控件。消息保留并入数据设置，紧凑目录控件、打开目录及保留期限自然排列，AI 工作目录可编辑和选择文件夹，长路径可横向查看。
- 消息变化只由正文与撤回状态决定。来源名、群名、发送者名、时间、附件缓存路径和独立回复关联等元数据变化不重传；回复按新消息身份处理。兼容原完整消息指纹，保留真实正文差异和未分析记录。
- 以本地更新时间游标分别管理过滤和分析，原始消息时间及插入时间保持；正文或撤回状态改变才更新时间，同毫秒多条更新及系统时钟回拨仍保证严格递增。归档复用既有事件边界游标，每批成功后独立推进；失败批次保留进度，前面已提交批次不重传。旧版本记录用于兼容及异常空洞，连续游标推进后清除已覆盖记录。过滤决定在完整请求实际预留时原子消费，不等待结果成功；同时记录完整批次已接收的消息版本，避免同一积压重新过滤；失败、取消、结果校验失败保留待处理消息，旧决定不再触发。保存失败或额度拒绝不消费，新决定不被旧请求完成清除。过滤版本表按有效待处理范围清理，避免固定条数驱逐造成反复触发。
- 标签显示与判断规则采用双列短卡片，重点关注人员编辑区收紧，窄窗口转为上下布局，保留失焦自动保存。
- 归档成功提示只在完成后的五分钟及同一上海日期内展示；失败/部分提交/进行中保留必要提示并显示时间。归档版本入口可查看历史执行记录，不删除原归档数据。
