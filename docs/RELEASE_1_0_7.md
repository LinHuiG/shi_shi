# 1.0.7 标签、模型来源与分析兼容修复

分支：`test`。

## 行为变化

- 标签目录组增加 `display_priority`，数值越小越靠前；初始等级 10、类型 20、其他组 100，同值稳定排序。设置中的“标签显示”可编辑，失焦保存，有版本检查和回滚；不改变事项等级排序、截止提级或真实标签赋值。列表、详情和筛选使用同一顺序，普通标签仅显示取值，悬停仍可查看类型。
- 右下角显示最近一次成功应用事项分析的时间，独立于调度尝试时间；失败、取消、扫描和其他用途不会推进。升级时可从当天已提交的 `analysis_result` 日志恢复，缺少可靠记录时不猜测历史成功时间。
- 模型目录改为有供应商、模型两列的可滚动列表，支持搜索和当前结果全选／反选。用途模型下拉始终带供应商前缀；同名供应商、同名模型仍保留不同路由，并在需要时补充源 ID，不修改传给供应商的原始模型 ID。
- 状态栏和开始／成功／失败日志使用本次请求捕获的接入、DSH 内部供应商及模型名称，不受运行中修改设置影响。分析会话入口与处置入口分开；DSH 显示其客户端查找说明与会话编号，API 不展示桌面会话跳转；旧记录不能确认来源时明确未知。通用表单、日志用量说明、处置提示去除写死的 Codex 文案，Codex 专属功能保留实际产品名称。
- 运行上下文保留一个标题，仍放在请求最后；消息列描述移入增量消息段。详细跟踪增加与前一份已保留请求的按段、JSON 字段及文本位置比较，明确“请求内容有变化”不代表业务事实冲突或缓存命中，保留完整原文和有界摘要说明。
- 用户可读生成文本使用自然中文；已知短编号可依据本次消息映射转换为真实发言人或“相关消息／事项”，证据字段仍保持可逆引用。源消息里本来存在的型号、代码不盲目替换；缺少当次映射的历史原文不猜改。
- API 识别明确的 `response_format type is unavailable` 拒绝提示，沿用一次受控兼容降级；不移除推理强度或工具，不放松最终 schema 验证。完整 JSON 约束同时提供给模型，并将重复约束计入输入预算。400 提示可安全标注被拒参数；失败前已收到的有效 token 用量保留，未确认部分仍标未知。
- WinHTTP 原生超时与请求期限同步，避免非流式推理被默认接收期限提前截断，继续支持总体期限和取消。[Microsoft WinHttpSetTimeouts 说明](https://learn.microsoft.com/en-us/windows/win32/api/winhttp/nf-winhttp-winhttpsettimeouts)记录了原生默认接收期限及设置方法。
- DSH 必须同时提供输入／输出计数才计入 token 用量，总数缺失时可求和。当前安装版 ACP 的 `usage_update` 为上下文容量，最终 prompt 仅返回停止原因，因此不能从它还原本次计费用量；界面明确说明，不把容量当调用计数。
