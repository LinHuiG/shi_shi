# 1.0.8 处置恢复、DSH 原生工作区与固定 AI 回归

分支：`test`。未修改正在运行的安装或用户个人提示词。

## 行为

- 处置会话按连接与执行端保留。切换来源而无对应会话时显示“重新处置”；切回原来源恢复原会话。明确未提交的错误可重试，未知提交结果仍先核实，避免重复执行。DSH 可转交 Codex，保留目录、事项和已保存结论，使用独立会话 ID；已有对应 Codex 会话可打开继续。
- 项目选择默认使用设置中的 AI 工作目录，允许手动切换。DSH 选择目录不再依赖 ACP 启动；深色 select/option 明确设置前景和背景，并保留系统高对比度回退。
- 移除事项“步骤与依赖”的生成、展示、编辑、合并与校验。旧步骤仅保留在历史存储中，不静默删除历史，不再传入 AI 上下文。
- DSH 与 API 保存原始结构化输出，修正成功后仍提示未返回的问题。请求 JSON key 递归规范排序，数组语义顺序保留；比较仅选择同用途、接入、模型和推理强度的请求。通用默认提示词不再绑定 Codex。
- DSH 账户模型目录插件存在写 stdout 的 console.info。启动时把 console 诊断重定向 stderr，保留直接写 stdout 的 ACP 消息和严格帧校验；使用正斜杠 preload 路径并恢复子进程原 NODE_OPTIONS。DeepSeek Chat Completions 的临时继承配置补齐缺失的 developer-role 兼容默认值，保留用户显式覆盖，不重写原 profile。
- 可选的最小 DSH desktop 插件只把 SS 发布的持久会话 ID 关联到原生工作区，复用原生列表和历史，不实现另一套聊天界面。设置中选择 DSH 接入后检测；缺失时显示“安装 SS 会话插件”，点击才写入插件及 insert 配置，保留原 YAML 和备份。首次安装后重启 DSH。插件还投影原生项目目录供 SS 选择。
- 归档 schema 补齐 memory_changes.task_id 的 required，并用 object/null 联合类型取代本地验证器不支持的 anyOf。

## 验证

- `cargo test --workspace --locked --offline`：427 通过、7 个既有忽略入口，无失败；所有 schema 的严格 required、可空类型、来源往返恢复、明确未提交与未知结果、目录解析及插件安装边界均有合成回归。
- 开发规范中的全部 17 个 Windows 无头 UI 套件通过；新增处置源切换、默认目录、失败重试、转交入口及旧步骤保留验证。独立 Node 测试验证原生工作区关联幂等、会话 ID 校验、console 与 ACP 通道分离及子进程 stdout 保持。
- 用户授权后使用当前连接配置、最小提示词与合成数据完成 Codex/DSH/API × 全部 12 用途的轻量真实矩阵，最终 36/36 通过；过滤、分析、处置与追问、报表、归档均覆盖。API 处置为预期能力拒绝且无模型调用。非 Codex 使用已配置可用的 DS 4.1 Flash，API 为 1017；不发明路由，先核对 DSH 实时目录。初始失败及修正后报告留在本地，不提交凭据、真实连接路径和会话记录。
- 当前安装的 DSH 版本在全新独立 home 实测：原生会话持久化、插件加载、原生工作区登记及会话成员关联通过；零模型调用。用户实际 desktop profile 未安装或修改。
