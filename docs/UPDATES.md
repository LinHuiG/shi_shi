# 版本更新

设置底部的“关于我们”显示当前版本，提供 GitHub、博客首页和拾事介绍入口。链接由系统默认浏览器打开。

版本后以小字显示“发布于”。未显式指定发布时间时，`build.rs` 自动读取构建机器的系统时间并嵌入产物，应用启动、检查更新和安装不会重新生成这个时间；关于页不显示安装或自动更新时间记录。`build.ps1` 每次打包生成临时构建标记，强制更新嵌入时间，即使源码没有变化也不会沿用旧产物时间。

自动更新默认开启，每次启动后检查一次公开仓库 `LinHuiG/shi_shi` 的最新正式 Release，发现可用新版本就下载并校验安装包。每次发起检查后，为下一次自动检查重新随机取 60～120 分钟的整数间隔；关闭自动更新后不自动检查，仍可手动检查。检查、下载和安装共用状态，重复点击不会重复发起请求。手动检查时按钮显示加载状态并禁用，不另显示一行检查说明；下载进度按文件大小显示。

确认暂无可用新版本后，按钮禁用并显示“暂无更新”，不另显示一行说明。从检查完成起保持 30 秒，然后自动恢复可点击的“检查更新”；轮询、切换页面不重新计时，到期不自动发送请求。检查失败保留重试能力，后台自动检查周期保持不变。

只有版本更高且发布时间晚于当前程序构建时间的正式版本可以更新。发布时间检查用于避免私仓测试版被较早发布的公开代码覆盖。预发布版本、草稿或缺少安装包、摘要的版本不会自动安装。

后台下载完成后不立即弹窗。开启自动更新时，每天北京时间 09:00 检查本地是否有已下载并校验的新包，有则弹窗提醒，提供“立即更新”“稍后更新”。稍后只关闭提醒。每天 04:00 独立检查本地新包，有则自动安装并重启拾事，无需先点击过稍后；两个检查各自每天只执行一次。

应用未运行、休眠越过时间或到点没有新包时，等第二天，不在启动、恢复或下载完成后补执行。关闭自动更新后不自动提醒或安装，手动检查与安装仍可用。定时请求只在当前分钟内有效，过期不重试；更新正在检查／下载／安装，或本地 AI 工作阻止安全重启时，跳过当天。Codex 桌面独立运行的处置不阻止拾事重启。

独立助手等待原进程退出，再以 NSIS 覆盖安装原程序目录，保留数据目录设置、已有数据和快捷方式选择，随后启动应用。只有安装完成且安装版本匹配后才记录更新时间。检查、下载或安装失败时提供错误信息，不将失败显示为成功更新。

## 发布包约定

- 使用 `vX.Y.Z` 或 `X.Y.Z` 的正式版本标签；安装包名为 `Shishi-Setup-X.Y.Z.exe`。
- 安装包必须是同一公开仓库 Release 的已上传资源；GitHub API 必须提供对应的 SHA-256 `digest`。下载前检查来源、文件名和大小，下载后以及安装前再次校验大小和 SHA-256。
- 下载仅接受 HTTPS 和 GitHub 的资源域名，限制重定向次数、文件大小及超时；网络请求使用当前 Windows 用户的代理设置。无需保存 GitHub 凭据。
- 已下载包、每日检查去重与更新记录保存在数据目录的 `updates/` 中。重启后保留有效包，但不补弹提醒或安装；开发运行目录可以检查和下载，自动安装要求程序来自正常安装目录。

## 离线验证

版本比较、发布时间、来源、摘要校验和更新时间使用合成资料验证；界面测试模拟检查、下载、稍后处理、确认、失败及重复点击。可控时钟另验证每日 09:00／04:00 的独立检查、跨日与持久去重、开关及缓存校验、启动／休眠／过期不补执行，不修改系统时间。原生验证仅在隔离目录执行安装和更新助手，不改变实际安装或下载并执行真实远端包。`--ui-smoke`、`--read-once` 和 `--no-auto-update` 不启动后台更新检查。

GitHub 匿名 API 请求受服务端额度限制，多个程序或共享代理出口可能共用额度。版本接口返回限流时，显示额度耗尽及响应提供的可重试时间；其他 HTTP 失败保留状态码，连接失败才使用网络提示。错误响应不作为无新版本结果，也不自动切换代理或保存 GitHub 凭据。

本地已有经过校验的新安装包时，原“检查更新”按钮显示“立即更新”，点击打开原有安装确认，不再发起网络检查，也不并排显示另一个重复更新按钮。刷新版本信息失败或未发现其他新版本时保留此前有效安装包，安装前仍重新校验。限流等待期间不会提前向 GitHub 发送请求；恢复时间未知时至少等待一分钟，等待结束不自动发起手动检查。

## 自动替换的进程边界

桌面父进程退出后，更新助手仅释放本安装路径、原进程身份和明确 MCP argv 同时匹配的辅助服务，不结束持有连接的外部客户端，也不处理其他安装。自动替换遇到主窗口或未知模式仍在运行时停止，交互安装保留原有确认。调用旧安装包前由新助手完成释放，新的 `/UPDATE` 安装包也支持同一流程。

失败的本地诊断写入数据目录 `updates/last-error.json`，保留已验证安装包与数据；成功后清除诊断。

测试包可显式指定 `build.ps1 -PublishedAt '<ISO 8601 with offset>'`，覆盖该包展示与更新比较使用的发布时间，构建指标记录该值。未传入时使用实际构建时间。
