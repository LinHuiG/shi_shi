拾事插件协议 1 / Windows x64

目录与依赖
插件是独立的动态库项目。主程序只认识本协议和统一消息模型；适配某软件的名称、路径规则、数据库结构、解码代码、依赖资源和迁移逻辑都属于插件。
安装包至少包含 plugin.json 和一个 DLL。可以压成 ZIP，用户在界面直接安装；plugin.json 可位于 ZIP 根目录或第一层包目录内，但 ZIP 只能含一个插件描述。只复制 manifest.files 中声明的资源，不允许绝对路径、上级目录、重解析点或链接。宿主不预装或自动加载任何插件。只加载用户在界面安装到 data/plugins/<id> 的包，旧版可执行文件旁的 plugins 目录不再自动加载。
消息来源页面的安装区域同时支持点击选择和拖入 ZIP。插件只管理安装与卸载；采集由接入源开关控制，没有启用来源时不运行采集。卸载会保留来源配置、消息和事项，并停用关联来源。重新安装后需按需启用来源。安装阶段仅校验描述与文件，不加载 DLL。普通配置表单自动调用 discover，单一候选自动填入全部配置；自定义配置页面直接加载，由页面决定何时发现账号。启用来源前宿主调用 validate，启用后调用读取接口。插件的静态初始化不得读取数据、创建线程或要求完整配置。

plugin.json
参见 examples/json-source/plugin.json。必需字段：id、name、version、api_version=1、entrypoint（相对DLL路径）、files、capabilities。config_fields 可省略，默认空列表。
id及配置字段key只允许字母、数字、短横线和下划线，1–64字符。
配置字段：key、label、type（file/directory/text/password）、required、description。宿主据此生成表单，支持文件和目录选择。password只遮挡UI显示，配置保存在用户的本地data中，插件不要返回不必要的凭据。
插件必须提供 discover、validate、fetch_incremental、fetch_range、lookup_messages。

页面内配置（主程序1.2.2起，可选）
settings={"api_version":1,"entrypoint":"settings.html","methods":["ui_load","ui_validate"]}，HTML必须列入files，最多2 MiB，方法名最多32个且不重复。
声明settings时直接在同一来源编辑页加载HTML，不先调用discover、不打开独立窗口。页面自行加载当前配置（新来源可能为空）、发现账号和展示错误；宿主管理来源名称，在标题右侧提供来源开关，不再展示名称输入框。
window.shishiPlugin.call(method,params={})返回Promise；只允许声明的方法。complete(config)完成字段检查、来源校验和持久保存后resolve并关页；失败reject且保留页面可重试，无须再点击第二次保存。cancel()直接离开；已由插件明确保存的文件不会回滚，保存来源期间不能取消。
主程序1.2.2起可选调用await shishiPlugin.suggestSourceName?.(name)，建议1–100字的来源名称。仅填入默认或空白名称草稿，同一编辑期间可更新前次建议；已有自定义名称不覆盖。返回true表示已填入，false表示保留现值；只有complete时才保存。
可选setDirty(boolean)报告实际配置草稿是否变化，搜索/筛选/滚动不算修改；返回Promise<boolean>表示是否接收。宿主只在启用及插件配置均未修改时允许点击应用内配置页外关闭，保存或选择路径期间不关闭；旧插件的输入事件保守标记修改。complete失败应维持修改状态，取消不提交。
主程序1.2.2起可选pickPath({kind:'file'|'directory',title,defaultPath,filters:[{name,extensions:['exe']}]})，通过宿主原生对话框选择路径，返回Promise<string|null>；取消返回null，不改变草稿、不保存。仅当前页面会话可调用。
可选setContentHeight(number|null)返回Promise<boolean>，传入自然内容高度（含内边距和底部操作），宿主按可用窗口限制配置页高度；null恢复填满可用空间。不得把iframe当前视口高度作为内容高度上报；重复值应去重，仅在内容或宽度变化时更新。
页面只支持内联脚本、内联样式及data图片，不能访问宿主DOM、网络或任意文件；本机能力通过call提供。
DLL另外导出uint8_t *shishi_plugin_settings_call(const uint8_t *input,size_t input_len,size_t *output_len,uint32_t (*cancelled)(uintptr_t),uintptr_t context)。输出仍用shishi_plugin_free释放，仍须shishi_plugin_abi()==1。
配置请求context含plugin_dir和timeout_ms=90000；config在打开会话时固定。取消回调与context只在调用期间有效。配置与采集共用一个无窗口插件工作进程，取消或90秒超时后终止；配置请求最多2 MiB，响应最多32 MiB。
宿主不导出SQLite ABI或共享sqlite3.dll；来源解密与数据库依赖由插件负责。完整教程见docs/PLUGIN_ADAPTATION.md。

C ABI（禁止跨 DLL 传 Rust String/Vec/trait 对象）
uint32_t shishi_plugin_abi(void); // 返回1
uint8_t *shishi_plugin_call(const uint8_t *input, size_t input_len, size_t *output_len);
void shishi_plugin_free(uint8_t *output, size_t output_len);
输入输出为 UTF-8 JSON，不依赖结尾0。由DLL分配输出，宿主调用同一DLL的free后才能卸载。单次请求/响应不超过32 MiB。
返回信封 {"ok":true,"result":...} 或 {"ok":false,"error":"说明"}。
plugin-sdk::export_plugin!(handler) 提供 Rust 导出、分配释放和 panic 捕获。
宿主在独立工作进程中串行调用所有插件，DLL按需加载并持续复用；普通业务失败不卸载DLL。致命异常、超时或在途取消会回收整个工作进程及子进程，后续调用重新创建。插件不要读取标准输入，也不要依赖标准输出（宿主用它们与工作进程通信，插件写入的输出会被忽略）。不要在调用返回后使用借用的回调、context或缓冲区。插件应遵守context.timeout_ms，正确释放自己的资源；内存状态可能随工作进程重建丢失。更新或卸载插件会回收工作进程。隔离不限制插件的本机权限。

请求
{"protocol":1,"method":"...","config":{...},"params":{...},"context":{"plugin_dir":"绝对包目录","work_dir":"可写临时目录","timeout_ms":90000}}
plugin_dir只读；资源相对它解析，临时文件写work_dir，支持 Unicode 和空格路径。读取原数据必须只读，不发送消息。

接口
discover: config可能缺字段。扫描已安装程序和数据位置，可结合用户的搜索目录。返回 {"candidates":[{"label":"可读说明","config":{完整候选配置}}],"warnings":["说明"]}。只返回已经校验的候选；多账号不默默选错。UI让用户选择候选、补齐后保存。
validate: 检查配置、文件内容和账号，返回 {"valid":true,"account_key":"稳定的来源身份","message":"说明"}。失败返回错误信封或valid=false。account_key用于防止更换账号后复用旧消息编号：同账号数据迁移应保持不变；通用文件来源可用规范化绝对文件路径。
fetch_incremental: params {"cursor":上次游标或null,"since":毫秒,"until":毫秒}。按范围读取，游标是插件私有JSON。返回 {"messages":[...],"cursor":新游标,"until":已成功读到的毫秒检查点}。宿主校验并成功保存消息后才提交游标。失败时不得跳过原游标，重试须幂等。
fetch_range: params {"since":毫秒,"until":毫秒}，包含首尾，返回同格式；宿主不会提交此游标。
lookup_messages: params {"ids":[原始消息编号],"until":当前毫秒}，返回 {"messages":[...]}，用于更新仍被事项跟踪的消息和撤回状态。未找到的ID可省略，不推断撤回。
fetch_scan（可选）: capabilities 声明后，宿主用一次隔离读取替代扫描时的 validate、fetch_incremental 和分批 lookup_messages；上述必需接口仍保留供旧宿主和配置页面调用。首次 params {"cursor":上次游标或null,"since":毫秒,"until":毫秒,"tracked":[去重后的原始消息编号]}，插件必须在同一冻结读取中校验配置与账号、读增量并补齐跟踪证据（含编辑和撤回）；增量已返回的证据无需重读。返回 {"valid":true,"account_key":"稳定身份","messages":[...],"cursor":新游标,"until":检查点,"next_page":"续页令牌或null"}。续页仍调用 fetch_scan，params 仅为 {"page":"上次返回的令牌"}；每页身份、游标和检查点必须相同，令牌不可重复，未结束页必须含消息，整轮消息身份（chat+id）不得重复。令牌最多128个ASCII字母、数字、短横线、下划线或冒号。插件应复用本轮冻结读取，不在每页重启读取环境；可将有界响应页放到 work_dir，不使用跨账号全局缓存。每次扫描使用独立UUID工作子目录，宿主在完成、失败或取消后清理；插件不得在调用返回后留存访问临时目录的后台任务。单轮最多100000条消息、少于10000次续页，单次请求/响应仍不超过32 MiB。失败不提交任何页或游标；旧插件继续使用原接口。

统一消息
必需 id（来源内稳定字符串）、time（Unix毫秒）、text（已经提取的可读文本）。建议完整提供：
{"id":"m1","chat":"c1","from":"u1","sender":"姓名","to":"u2","recipient":"对方","group":"会话名称","time":1792051200000,"text":"请确认发布安排","kind":"text","mention_me":false,"mention_all":false,"private":true,"mine":false,"withdrawn":false,"reply":""}
宿主为消息、会话、发送接收方和回复ID加来源前缀；插件收到的lookup IDs仍为原始ID。插件不要填source_id/source_name/external_id，由宿主写入。
withdrawn=true时宿主清空text，并处理相关证据。只把正文放text，不把软件协议元数据、隐式命令或卡片动作链接交给宿主猜测。附件可返回可读占位说明。

示例开发与验证
cargo build --workspace --release --locked
将 target/release/shishi_json_source.dll 与 examples/json-source/plugin.json 放在同一目录，安装该描述文件或整个 ZIP 包即可。
设置 SHISHI_TEST_PLUGIN 为此示例插件包目录或 ZIP 文件，可运行 cargo test native_json_plugin -- --ignored 测试真实DLL和多来源读取；只使用自动生成的测试数据，不会调用AI。

图片附件（可选，主程序0.3.8起）：消息可带 images:[{id:string,path:string}]，最多8项。path为本地已缓存栅格图片绝对路径，不可用时填空；主程序重新命名id，不把路径发给模型。来源插件负责限定到本账号数据目录，不提供任意URL下载或无关文件。撤回消息必须清空images。支持PNG/JPEG/GIF/BMP，原始文件最多10MiB。仅在用户预览或AI明确read_image时解码，自动分析每批最多2次。旧插件无需此字段仍兼容。
