拾事ShiShi
==========
Windows桌面AI事项助手

把聊天消息整理成事项，跟进进展，再把需要调查和处置的任务交给AI。
拾事保留消息依据、处理记录和可编辑的记忆，方便查看待办、安排任务、追踪结果。

项目与下载：https://github.com/LinHuiG/shi_shi
更新记录：https://github.com/LinHuiG/shi_shi/releases

主要功能
--------
· 消息：插件读取、增量导入、去重和收件箱查询。
· 事项：AI整理或手动创建，管理状态、等级、截止时间、标签和定时事项。
· 处置：在Codex或DSH中开始调查并交给客户端继续，进展通过CLI写回事项。
· 跟进：定时分析、早报、下班汇总、归档和事项变更提醒。
· 经验：查看和编辑AI记忆，预览并决定是否采用提示词、规则与标签建议。

开始使用
--------
1. 准备Windows x64和Microsoft Edge WebView2 Runtime。
2. 在设置中添加AI连接，为需要使用的用途选择模型。用途模型留空时不调用模型。
3. 可以先手动创建事项。需要接入消息时，在“消息来源”中安装可信插件并配置数据位置。
4. 查看消息依据、调整事项状态，或选择模型开始调查与处置。

Codex CLI支持分析，Codex桌面端执行处置；DeepSeek Harness（ACP）支持分析与处置，
兼容HTTPS API支持分析。安装包默认不附带消息来源插件。

数据与后台
----------
消息、事项和配置默认保存在程序目录下的data，可以在设置中更改目录。
调用AI时，相关内容会发送给所选后端。API密钥使用Windows DPAPI保存，
也可从指定环境变量读取；完整AI跟踪默认关闭。

插件在独立工作进程中运行，仍具有当前用户的文件和网络权限。
只安装可信插件，仅读取已授权的数据。

自动任务需要后台保持运行。关闭窗口会隐藏到托盘；托盘“退出”释放图形端。
shishi.exe同时是命令行入口，CLI后台的运行与退出方式见随包CLI.md。
让agent读取skills/shishi-cli/SKILL.md即可了解命令用法。

更新与旧版数据
--------------
开启自动更新后，每天凌晨04:00安装已下载的新版本并重启。
需要电脑和拾事保持运行；错过该时间不会补执行。
手动覆盖安装可选择强制退出当前安装目录的拾事及后台。

1.2.5使用新的数据格式。安装器尝试把兼容的旧state.sqlite3转换到shishi.db，
迁移基础事项、工具、提示词、记忆、来源和AI配置。
旧消息、定时计划和运行历史不会转入；无法转换的记录跳过并记日志，原文件保留。
覆盖安装保留已有的数据目录设置。
